How fast is it?

Measured on an Apple silicon Mac with a release build:

  • git/git, with 86,000 commits, opens in about 150 ms. A 6,000 commit repository opens in about 20 ms.
  • The Linux kernel, with almost 1.5 million commits, opens in about a second and a half and adds roughly 250 MB of memory.
  • A frame takes well under a millisecond to draw while you scroll, because Kelp only draws the rows you can see.
  • When you are not using it, Kelp uses 0% CPU. It only redraws when you do something or when background work finishes.

If a repository has no commit-graph file, Kelp writes one in the background with git commit-graph write. That makes every later open much faster. The full numbers are in the ledger.

Does Kelp collect any data?

No. Kelp has no telemetry, no analytics and no crash reporting. It never sends your code, file names or commit messages anywhere. The only network requests it makes are the ones listed below.

What network requests does Kelp make?

Avatars

To show faces next to commits, Kelp asks GitHub for the avatar of commit authors (avatars.githubusercontent.com, and api.github.com to match a commit to its author on GitHub repositories), then Gravatar, which receives a SHA-256 hash of the email address, not the address itself. Only authors of commits on screen are looked up, and images are cached on disk. Turn this off with Settings > Load avatars from GitHub and Gravatar; you get generated initials instead.

The update check

Five seconds after launch and then every six hours, Kelp asks api.github.com for the latest release of Kelp. If you installed with Homebrew, it can install the update with brew upgrade in the background. Both are switches in Settings.

Pull requests and CI checks

On repositories hosted on GitHub, Kelp shows pull requests on your branches and a CI status dot on commits. Pull requests come through the GitHub CLI (gh) when it is installed, using your own gh login, and from the public GitHub API otherwise. CI status needs gh. Results are cached for five minutes and refreshed after you fetch, pull or push. Repositories not on GitHub make no such requests.

Your own git remotes

Kelp fetches from your remotes in the background every 5 minutes, the same as running git fetch. Change the interval or turn it off in Settings. Pull, push and clone talk to your remotes only when you ask.

Every git and gh command Kelp runs shows up in the git console (Cmd+Opt+L), with its output.

Where does Kelp keep its files?

WhatWhere
Settings, open tabs, recent repositories, window size, panel sizes and zoom~/Library/Application Support/kelp/settings.json
Avatar, pull request and CI caches~/Library/Caches/kelp
Review comments<repo>/.git/kelp/comments.json
Per-repository preferences: sidebar layout, hidden branches, commit box options<repo>/.git/kelp/
Undo snapshots, removed the next time the repository opensrefs/kelp/undo inside the repository

Files inside .git are never committed or pushed. To reset Kelp, quit it and delete the kelp folders above.

Does Kelp run on Linux?

Not yet. Kelp is built and tested for macOS 12 or later. The code has Linux paths for fonts, caches, settings and opening a terminal, and it may build from source, but nobody has tested it there, so expect rough edges. Windows would be nice to have, but it is not a target for now.

How do I report a bug?

Open an issue on GitHub. You can also get there from Settings > Help > Report a bug, or by typing "report a bug" in the command palette. These help us find the cause:

  • Your Kelp version (kelp --version) and macOS version.
  • What you did, what you expected and what happened instead.
  • If a git command failed, the lines from the git console (Cmd+Opt+L).
  • A screenshot, if it's something you can see.

Please don't paste anything private from your repository. A small public repository that shows the problem is the best report.
